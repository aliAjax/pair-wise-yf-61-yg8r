# 远程设备固件分批发布控制台

可恢复的发布账：把**设备分组、发布批次、遥测回执**整理成一套断电可续、并发可判、旧账可查的账本。

## 技术栈

Angular、TypeScript、Angular Material、NgRx、RxJS、Angular CDK、Transloco。

## 本地运行

```bash
npm install
npm run dev        # 开发端口 62026
npm run build      # 生产构建
npm run test:ledger # 纯领域账本单元测试（node:test，无需额外依赖）
```

## 发布账规则

- **按设备号记账**：每个批次为每台目标设备保留一条账，依次记录下载、安装、重启事件；重复回执（同号重发、阶段倒退重报）只出现一次，不推进修订号。
- **发布窗口（分组互斥）**：一个分组同一时刻只允许一个运行/暂停中的批次占用；占用期间新批次进入等候队列，占用者完成或回滚后队首自动接管窗口。
- **离线晚到回执不污染进度**：批次暂停/回滚/等候/完成期间到达的回执只进入暂存，绝不计入；恢复或接管窗口时按**当前批次版本**重放，版本不符或已离开目标集合的立即作废。
- **版本变更即重算**：批次固件版本一变，仅下载（未执行）的账上记录与暂存回执立即失效，目标设备按新版本重算；已安装/已重启的设备结果保留为历史、不再进入新版本目标，也不计入当前进度。
- **并发提交冲突可见**：每个批次带单调递增修订号（revision）。两名值班员同时提交同一批回执时，后到者若基于旧修订号，整批被拒并返回冲突设备清单（含设备当前阶段）与最新修订号，同步后可重新提交。
- **可恢复存储**：提交先过账本校验，再走存储端口；落盘部分失败时，已完成设备的账保留，只有未完成回执保留在 `storageFailed` 中，可只重试这部分（重试前会再次核对设备当前阶段，已被其他途径补齐的自动跳过）。
- **旧账升级只读**：localStorage 中缺少批次版本字段的 v1 旧数据启动时自动迁移为 `历史只读` 批次，可查看、不能再提交回执或变更版本；新账写入 `firmware-release-v2` 键。
- **进度全部由账重算**：下载/安装/重启数量与百分比均从当前版本的设备账实时派生，不存在游离计数器。

## 代码结构

- `src/app/state/release.models.ts` — 账本数据模型（设备账、暂存、保留结果、提交结果）。
- `src/app/state/release.ledger.ts` — 纯领域规则（无 Angular 依赖）：窗口排队、回执去重/暂存/重放、版本失效、修订号冲突、断点重试。
- `src/app/state/release.storage.ts` — v1→v2 迁移、种子账、可恢复启动。
- `src/app/state/release.reducer.ts` — NgRx 薄封装与遥测模拟（模拟数据也走同一条提交链路）。
- `src/app/state/release.ledger.spec.ts` — 覆盖上述全部规则的 11 个单元测试。

## 控制台演练路径

1. 顶部窗口看板显示每个分组谁在占用、谁在等候。
2. 种子中「边缘网关安全补丁 2.8.1」正占用 g-edge；再建一个同分组批次会自动排队。
3. 暂停运行批次后手动提交回执 → 看到"暂存不计账"；继续 → 暂存按当前版本重放。
4. 「变更版本」按钮可把 2.8.1 改成新版本，观察仅下载设备清零、已安装设备进入保留历史。
5. 两名值班员演练：记住当前修订号，先提交一条，再用旧修订号提交同一台设备 → 冲突卡片列出设备与最新修订号。
6. 存储故障面板可让全部/指定设备回执落盘失败，再用"只重试未完成设备"补齐。
7. 历史只读批次来自迁移演示，拒绝一切写操作。
